
# 松原市燃气安全监管平台 - 增强版整体架构设计

> 版本：2.0-Enhanced
> 更新日期：2026-01-29
> 基于燃气专题功能清单的增强版架构设计

---

## 一、文档说明

### 1.1 文档目的

本文档是松原市市政基础设施生命线（燃气）安全监管平台的**增强版整体架构设计**，整合：
- **第一版需求**：`requirements/松原市市政基础设施生命线（燃气）安全监管平台建设项目初步设计.md`
- **燃气专题功能清单**：`requirements/燃气功能清单.csv`（城市生命线燃气专题标准功能）
- **技术框架**：ruoyi-vue-pro（Spring Boot 3.x + Vue3）

### 1.2 功能清单来源对比

| 来源 | 定位 | 核心内容 |
|------|------|----------|
| 第一版需求 | 松原市项目定制 | 巡查防控、督查检查、安全培训、应急调度 |
| 燃气专题清单 | 城市生命线标准产品 | 管网监测、燃沼辨识、风险评估、泄漏溯源 |

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| **DDD领域驱动** | 按业务领域划分模块，明确限界上下文和聚合根 |
| **双轨融合** | 第一版需求 + 燃气专题清单功能融合 |
| **BPMN 2.0** | 复杂审批流程使用Flowable工作流引擎 |
| **框架复用** | 充分利用ruoyi-vue-pro现有能力 |
| **GIS一体化** | 空间数据统一通过GIS模块管理 |

### 3.2 核心域详细设计

#### 3.2.1 监测预警域 (Monitoring Domain)

**领域职责**：设备数据采集、实时监测、报警研判、燃沼辨识、泄漏预警、预警处置

**核心能力**：
- **燃沼辨识**：区分燃气泄漏和沼气聚集（核心算法）
- **多源数据融合**：可燃气体浓度、管网振动、压力数据综合分析
- **智能预警**：基于规则引擎和AI算法的预警生成

**聚合根**：
- `MonitoringDevice`（监测设备）：设备信息、运行状态、监测数据
- `MonitoringPoint`（监测点位）：测点信息、关联设备、阈值配置
- `Alarm`（报警）：报警信息、报警类型、处置流程
- `Warning`（预警）：预警信息、预警等级、联动处置
- `WarningWorkOrder`（预警工单）：工单信息、派发记录、处置结果

**核心实体**：
- `MonitoringData`（监测数据）：实时数据、历史数据、统计数据
- `AlarmRule`（报警规则）：阈值配置、触发条件、通知规则
- `GasMethaneAnalysis`（燃沼辨识分析）：特征对比、辨识结果

**领域服务**：
- `DataCollectionService`：数据采集、数据清洗、数据存储
- `AlarmJudgmentService`：报警判断、规则匹配、等级评估
- `GasMethaneIdentificationService`：**燃沼辨识算法服务**
- `WarningGenerationService`：预警生成、预警分级
- `WarningDispatchService`：预警工单派发、处置跟踪

**领域事件**：
- `AlarmTriggeredEvent`：报警触发事件
- `GasLeakageWarningEvent`：燃气泄漏预警事件
- `MethaneWarningEvent`：沼气聚集预警事件
- `WarningWorkOrderCreatedEvent`：预警工单创建事件
- `WarningWorkOrderClosedEvent`：预警工单关闭事件

**对外接口**：
- 提供监测数据查询接口
- 提供报警信息订阅接口
- 提供预警信息查询接口
- 接收设备数据上报接口

#### 3.2.2 风险评估域 (RiskAssess Domain)

**领域职责**：管网风险评估、风险分级、风险四色图、风险管控

**核心能力**：
- **风险评估模型**：基于管材、管龄、压力等级、周边环境的风险评估
- **风险四色图**：红橙黄蓝四色风险等级GIS可视化
- **动态评估**：基于监测数据、隐患数据的动态风险评估

**聚合根**：
- `PipelineRiskAssessment`（管网风险评估）：评估对象、评估结果、风险等级
- `RiskAssessmentModel`（风险评估模型）：评估因子、权重配置、评估算法
- `RiskControlMeasure`（风险管控措施）：管控要求、巡检频次、应急预案

**核心实体**：
- `RiskFactor`（风险因子）：因子类型、因子值、权重
- `RiskLevel`（风险等级）：等级定义、颜色标识、管控要求

**领域服务**：
- `RiskAssessmentService`：风险评估计算、等级判定
- `RiskFourColorMapService`：风险四色图生成、GIS渲染
- `RiskControlService`：风险管控措施制定、执行跟踪

**领域事件**：
- `RiskAssessmentCompletedEvent`：风险评估完成事件
- `HighRiskIdentifiedEvent`：高风险识别事件

**对外接口**：
- 提供风险评估结果查询接口
- 提供风险四色图数据接口
- 接收管网基础数据更新接口
- 接收监测数据订阅接口

#### 3.2.3 应急调度域 (Emergency Domain)

**领域职责**：预警发布、事件处置、预案管理、资源调度

**聚合根**：
- `EmergencyWarning`（应急预警）：预警信息、发布流程、响应记录
- `EmergencyEvent`（应急事件）：事件信息、处置流程、结案总结
- `EmergencyPlan`（应急预案）：预案内容、结构化数据、版本管理
- `EmergencyResource`（应急资源）：资源信息、调度记录、状态管理

**核心实体**：
- `WarningLevel`（预警等级）：等级定义、响应要求、审批流程
- `EventLevel`（事件等级）：等级定义、影响评估、处置要求
- `ResourceDispatch`（资源调度）：调度指令、执行反馈、到位情况

**领域服务**：
- `WarningPublishService`：预警发布、多渠道推送
- `EventAssessService`：事件研判、等级评估
- `PlanMatchService`：预案匹配、自动启动
- `ResourceScheduleService`：资源查询、就近调度

**领域事件**：
- `EmergencyWarningPublishedEvent`：应急预警发布事件
- `EmergencyEventReportedEvent`：应急事件上报事件

- 提供应急资源查询接口
- 接收监测预警事件订阅
- 接收巡查隐患事件订阅

### 3.3 支撑域详细设计

#### 3.3.1 基础设施域 (Infrastructure Domain)

**领域职责**：管网管理、场站管理、设备管理、危险源管理、防护目标管理、测点管理

**业务特点**：
- **物理资产管理**：聚焦燃气基础设施的物理资产
- **空间数据为主**：大量GIS空间数据
- **变更频率低**：管网、场站等基础设施变化较少
- **专业性强**：需要燃气专业知识

**核心能力**：
- **管网GIS数据管理**：管线、管点、阀门、调压设施的空间数据
- **管网拓扑分析**：管网连通性、关阀影响分析
- **设备全生命周期**：设备台账、运维、状态监测、统计分析
- **危险源与防护目标**：危险源识别、防护目标管理

**聚合根**：
- `Pipeline`（管线）：管线信息、空间数据、属性数据
- `PipelineNode`（管点）：管点类型、位置、连接关系
- `Valve`（阀门）：阀门信息、位置、状态、操作记录
- `Regulator`（调压设施）：调压器/调压箱信息、参数配置
- `Station`（场站）：场站信息、设备配置、安全设施
- `MonitoringDevice`（监测设备）：设备台账、运维记录、状态
- `MonitoringPoint`（监测点位）：测点信息、关联设备、阈值配置
- `HazardSource`（危险源）：危险源信息、分级、空间分布
- `ProtectionTarget`（防护目标）：防护目标信息、影响范围

**核心实体**：
- `DeviceMaintenance`（设备维护）：维护计划、维护记录
- `DeviceFault`（设备故障）：故障信息、处理记录
- `PipelineSegment`（管段）：管线分段信息

**领域服务**：
- `PipelineTopologyService`：管网拓扑分析、连通性分析
- `ValveImpactAnalysisService`：关阀影响分析
- `DeviceLifecycleService`：设备全生命周期管理
- `HazardSourceAssessService`：危险源评估服务
- `GISDataService`：GIS数据处理、空间分析

**领域事件**：
- `PipelineCreatedEvent`：管线创建事件
- `ValveOperatedEvent`：阀门操作事件
- `DeviceFaultEvent`：设备故障事件

**对外接口**：
- 提供管网数据查询接口（供监测、风险评估、泄漏溯源使用）
- 提供设备信息查询接口（供监测使用）
- 提供阀门信息查询接口（供泄漏溯源使用）
- 提供危险源/防护目标查询接口（供风险评估、应急调度使用）
- 提供管网拓扑分析接口

#### 3.3.2 组织资源域 (Organization Domain)

**领域职责**：企业管理、人员管理、应急队伍管理、应急物资管理

**业务特点**：
- **组织资源管理**：聚焦人和组织
- **业务数据为主**：非空间数据
- **变更频率中**：人员流动、资质更新
- **通用性强**：通用的组织管理模式

**核心能力**：
- **企业全生命周期**：企业注册、资质管理、年检、注销
- **人员资质管理**：人员信息、资质证书、培训记录
- **应急资源管理**：应急队伍、应急物资、专家库

**聚合根**：
- `Enterprise`（企业）：企业信息、资质证照、经营范围
- `Personnel`（人员）：人员信息、资质证书、培训记录
- `EmergencyTeam`（应急队伍）：队伍信息、人员配置、装备情况
- `EmergencyMaterial`（应急物资）：物资信息、库存数量、存放位置
- `Expert`（专家）：专家信息、专业领域、联系方式

**核心实体**：
- `EnterpriseQualification`（企业资质）：资质类型、有效期、证书编号
- `PersonnelCertificate`（人员证书）：证书类型、有效期、发证机关
- `MaterialInventory`（物资库存）：库存记录、出入库记录

**领域服务**：
- `EnterpriseQualificationService`：企业资质审核、年检提醒
- `PersonnelCertificationService`：人员资质认证、到期提醒
- `EmergencyResourceService`：应急资源查询、调度支持

**领域事件**：
- `EnterpriseRegisteredEvent`：企业注册事件
- `PersonnelCertifiedEvent`：人员认证事件
- `QualificationExpiredEvent`：资质到期事件

**对外接口**：
- 提供企业信息查询接口
- 提供人员信息查询接口
- 提供应急资源查询接口（供应急调度使用）
- 提供专家信息查询接口（供知识管理使用）

#### 3.3.3 巡查防控域 (Patrol Domain)

**领域职责**：巡查计划制定、任务生成分派、现场执行、隐患整改

**核心能力**：
- **风险驱动巡检**：基于风险评估结果调整巡检频次
- **移动端作业**：现场巡检数据采集、问题上报
- **隐患闭环管理**：发现→整改→验收全流程

**聚合根**：
- `PatrolPlan`（巡查计划）：计划信息、周期规则、作业内容
- `PatrolTask`（巡查任务）：任务信息、执行状态、检查结果
- `Hazard`（隐患）：隐患信息、整改流程、验收记录

**核心实体**：
- `CycleRule`（周期规则）：周期配置、触发条件、生效范围
- `WorkContent`（作业内容）：检查项、评分标准、表单模板
- `PatrolRecord`（巡查记录）：签到签退、检查结果、现场照片
- `RectifyRecord`（整改记录）：整改措施、整改进度、验收结果

**领域服务**：
- `PlanGenerateService`：计划自动生成、任务拆分
- `TaskAssignService`：任务分配、负载均衡
- `HazardRectifyService`：整改流程、超期预警
- `RiskBasedPatrolService`：基于风险等级调整巡检频次

**领域事件**：
- `HazardReportedEvent`：隐患上报事件（通知应急调度）
- `HazardClosedEvent`：隐患关闭事件（更新风险评估）

#### 3.3.3 督查检查域 (Inspection Domain)

### 3.4 高级域详细设计

#### 3.4.1 泄漏研判分析域 (LeakageAnalysis Domain)

**领域职责**：泄漏溯源分析、关阀方案建议、扩散模拟、爆炸影响分析

**核心能力**：
- **泄漏溯源**：基于监测数据和管网拓扑推演泄漏管段
- **关阀优化**：计算最优关阀方案，最小化影响范围
- **扩散模拟**：模拟燃气在地下空间的扩散过程
- **爆炸分析**：评估爆炸风险、计算影响范围

**聚合根**：
- `LeakageAnalysisTask`（泄漏分析任务）：分析任务、输入参数、分析结果
- `ValveClosurePlan`（关阀方案）：关阀顺序、影响范围、影响用户
- `DiffusionSimulation`（扩散模拟）：模拟参数、扩散范围、时间序列
- `ExplosionAnalysis`（爆炸分析）：爆炸半径、影响建筑、影响人口

**核心实体**：
- `LeakageSegment`（泄漏管段）：推演的泄漏管段、置信度
- `AffectedUser`（影响用户）：关阀影响的用户列表
- `AffectedBuilding`（影响建筑）：爆炸影响的建筑物
- `EvacuationRoute`（疏散路线）：人员疏散路线规划

**领域服务**：
- `LeakageTracebackService`：泄漏溯源算法服务
- `ValveClosureOptimizationService`：关阀方案优化服务
- `GasDiffusionSimulationService`：燃气扩散模拟服务
- `ExplosionImpactAnalysisService`：爆炸影响分析服务
- `EvacuationPlanningService`：疏散路线规划服务

**领域事件**：
- `LeakageAnalysisCompletedEvent`：泄漏分析完成事件
- `ExplosionRiskIdentifiedEvent`：爆炸风险识别事件

**对外接口**：
- 接收监测预警触发分析
- 提供分析结果查询接口
- 提供GIS可视化数据接口

### 5.3 权限实现方案

#### 5.3.1 基于 ruoyi-vue-pro 的权限体系

```
┌─────────────────────────────────────────────────────────────────┐
│                    权限实现架构                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 功能权限（Menu + Permission）                            │   │
│  │ • 菜单权限：控制用户可见的菜单项                          │   │
│  │ • 按钮权限：控制用户可操作的按钮（增删改查）              │   │
│  │ • 实现方式：@PreAuthorize("@ss.hasPermission('xxx')")    │   │
│  └─────────────────────────────────────────────────────────┘   │
│                          ↓                                      │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 数据权限（Data Scope）                                   │   │
│  │ • 全部数据：DATA_SCOPE_ALL                               │   │
│  │ • 部门数据：DATA_SCOPE_DEPT                              │   │
│  │ • 部门及以下：DATA_SCOPE_DEPT_AND_CHILD                  │   │
│  │ • 本人数据：DATA_SCOPE_SELF                              │   │
│  │ • 自定义：DATA_SCOPE_CUSTOM                              │   │
│  │ • 实现方式：@DataPermission 注解                         │   │
│  └─────────────────────────────────────────────────────────┘   │
│                          ↓                                      │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 租户隔离（Tenant）                                       │   │
│  │ • 企业级数据隔离                                          │   │
│  │ • 实现方式：TenantDatabaseInterceptor                    │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### 5.3.2 燃气平台权限扩展

针对燃气监管平台的特殊需求，需要扩展以下权限能力：

| 扩展项 | 说明 | 实现方式 |
|--------|------|----------|
| 行政区划权限 | 市-县-乡三级数据隔离 | 扩展 DataScope，增加区划字段 |
| 企业数据权限 | 监管部门可查看辖区企业数据 | 自定义数据权限规则 |
| 跨企业协作 | 应急场景下跨企业数据共享 | 临时授权机制 |
| 敏感数据脱敏 | 部分角色查看脱敏数据 | 数据脱敏拦截器 |

```java
// 功能权限示例

    @DataColumn(key = "deptId", value = "dept_id"),
    @DataColumn(key = "userId", value = "creator")

public List<PatrolTaskDO> getPatrolTaskList() { ... }

// 区划权限示例（扩展）
@AreaPermission(level = AreaLevel.COUNTY)
```
