## 一、文档说明

### 1.1 文档目的

本文档是松原市市政基础设施生命线（燃气）安全监管平台的**增强版整体架构设计**，基于：
- 原始需求：`requirements/松原市市政基础设施生命线（燃气）安全监管平台建设项目初步设计.md`
- 竞品调研：`requirements/燃气功能清单.xlsx`（73项功能）
- 技术框架：ruoyi-vue-pro（Spring Boot 3.x + Vue3）

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **DDD领域驱动** | 按业务领域划分模块，明确限界上下文和聚合根 |
| **业务流优先** | 先梳理业务流程，再设计技术实现 |
| **BPMN 2.0** | 复杂审批流程使用Flowable工作流引擎 |
| **框架复用** | 充分利用ruoyi-vue-pro现有能力 |
| **GIS一体化** | 空间数据统一通过GIS模块管理 |
| **松耦合** | 领域间通过事件驱动解耦 |

## 二、项目概述

### 2.1 项目背景

松原市作为吉林省重要的能源城市，燃气管网覆盖广、用户量大。为提升燃气安全监管能力，建设城市生命线（燃气）安全监管平台，实现：

- **全面感知**：燃气管网、场站、用户侧的全方位实时监测
- **智能预警**：基于多源数据融合的风险识别和预警
- **协同处置**：市-县-乡三级联动的问题处置闭环
- **应急调度**：快速响应的应急指挥调度体系
- **数据驱动**：燃气安全态势感知和决策支持

### 2.2 建设目标

### 4.4 核心域详细设计

#### 4.4.1 监测预警域 (Monitoring Domain)

**领域职责**：设备数据采集、实时监测、报警研判、预警生成

**聚合根**：
- `MonitoringDevice`（监测设备）：设备信息、运行状态、监测数据
- `Alarm`（报警）：报警信息、处置流程、关联数据
- `AlarmRule`（报警规则）：阈值配置、触发条件、通知规则

**核心实体**：
- `MonitoringPoint`（监测点位）：监测位置、关联设备、阈值配置
- `MonitoringData`（监测数据）：实时数据、历史数据、统计数据
- `AlarmRecord`（报警记录）：报警历史、处置记录、统计分析

**领域服务**：
- `DataCollectionService`：数据采集、数据清洗、数据存储
- `AlarmJudgmentService`：报警判断、规则匹配、等级评估
- `AlarmNotifyService`：报警通知、消息推送、短信发送

**领域事件**：
- `AlarmTriggeredEvent`：报警触发事件
- `AlarmConfirmedEvent`：报警确认事件
- `AlarmClosedEvent`：报警关闭事件

**对外接口**：
- 提供设备数据查询接口
- 提供报警信息订阅接口
- 接收设备数据上报接口

#### 4.4.2 巡查防控域 (Patrol Domain)

**领域职责**：巡查计划制定、任务生成分派、现场执行、问题整改

**聚合根**：
- `PatrolPlan`（巡查计划）：计划信息、周期规则、作业内容
- `PatrolTask`（巡查任务）：任务信息、执行状态、检查结果
- `Hazard`（隐患）：隐患信息、整改流程、验收记录

**核心实体**：
- `CycleRule`（周期规则）：周期配置、触发条件、生效范围
- `WorkContent`（作业内容）：检查项、评分标准、表单模板
- `CheckItem`（检查项）：检查内容、检查标准、结果类型
- `PatrolRecord`（巡查记录）：签到签退、检查结果、现场照片
- `RectifyRecord`（整改记录）：整改措施、整改进度、验收结果

**领域服务**：
- `PlanGenerateService`：计划自动生成、任务拆分
- `TaskAssignService`：任务分配、负载均衡
- `HazardRectifyService`：整改流程、超期预警

**领域事件**：
- `TaskCreatedEvent`：任务创建事件
- `TaskCompletedEvent`：任务完成事件
- `HazardReportedEvent`：隐患上报事件
- `HazardClosedEvent`：隐患关闭事件

**对外接口**：
- 提供巡查任务查询接口
- 提供隐患信息查询接口
- 接收问题上报接口

#### 4.4.3 应急调度域 (Emergency Domain)

**领域职责**：预警发布、事件处置、预案管理、资源调度

**聚合根**：
- `Warning`（预警）：预警信息、发布流程、响应记录
- `EmergencyEvent`（应急事件）：事件信息、处置流程、结案总结
- `EmergencyPlan`（应急预案）：预案内容、结构化数据、版本管理
- `EmergencyResource`（应急资源）：资源信息、调度记录、状态管理

**核心实体**：
- `WarningLevel`（预警等级）：等级定义、响应要求、审批流程
- `EventLevel`（事件等级）：等级定义、影响评估、处置要求
- `PlanElement`（预案要素）：组织体系、响应程序、处置措施
- `ResourceDispatch`（资源调度）：调度指令、执行反馈、到位情况
- `EmergencyTeam`（应急队伍）：队伍信息、人员配置、装备情况
- `EmergencyExpert`（应急专家）：专家信息、专业领域、联系方式

**领域服务**：
- `WarningPublishService`：预警发布、多渠道推送
- `EventAssessService`：事件研判、等级评估
- `PlanMatchService`：预案匹配、自动启动
- `ResourceScheduleService`：资源查询、就近调度

**领域事件**：
- `WarningPublishedEvent`：预警发布事件
- `EventReportedEvent`：事件上报事件
- `PlanActivatedEvent`：预案启动事件
- `ResourceDispatchedEvent`：资源调度事件

**对外接口**：
- 提供预警信息查询接口
- 提供应急资源查询接口
- 接收报警事件订阅
- 接收问题事件订阅

### 4.5 支撑域详细设计

#### 4.5.1 资源管理域 (Resource Domain)

**领域职责**：企业管理、管网管理、设施管理、人员管理

**聚合根**：
- `Enterprise`（企业）：企业信息、资质证照、经营范围
- `PipelineNetwork`（管网）：管网信息、拓扑关系、GIS数据
- `Facility`（设施）：设施信息、运行状态、维护记录
- `Personnel`（人员）：人员信息、资质证书、培训记录

**核心实体**：
- `Pipeline`（管线）：管线信息、材质管径、埋深年限
- `PipelineNode`（管点）：管点信息、类型位置、连接关系
- `Station`（场站）：场站信息、设备配置、安全设施
- `Valve`（阀门）：阀门信息、位置状态、操作记录
- `Regulator`（调压设施）：调压器信息、参数配置、运行数据

**领域服务**：
- `PipelineTopologyService`：管网拓扑分析、连通性分析
- `FacilityMaintenanceService`：设施维护计划、维护记录

**对外接口**：
- 提供企业信息查询接口
- 提供管网数据查询接口
- 提供设施信息查询接口
- 提供人员信息查询接口

#### 4.5.2 督查检查域 (Inspection Domain)

**领域职责**：督查计划、现场检查、问题整改、整改验收

**聚合根**：
- `InspectionPlan`（督查计划）：计划信息、检查范围、检查内容
- `InspectionTask`（检查任务）：任务信息、检查记录、问题清单
- `InspectionIssue`（检查问题）：问题信息、整改要求、验收记录

**核心实体**：
- `InspectionRecord`（检查记录）：检查时间、检查人员、检查结果
- `RectificationNotice`（整改通知）：通知内容、整改期限、责任单位

**领域服务**：
- `InspectionScheduleService`：检查任务调度、人员分配
- `IssueTrackingService`：问题跟踪、超期预警

#### 4.5.3 安全培训域 (Training Domain)

**领域职责**：培训计划、课程管理、在线学习、考试考核

**聚合根**：
- `TrainingPlan`（培训计划）：计划信息、培训对象、培训内容
- `Course`（课程）：课程信息、课件资源、学习要求
- `Exam`（考试）：考试信息、试题试卷、考试记录
- `Certificate`（证书）：证书信息、有效期限、发放记录

**核心实体**：
- `CourseResource`（课程资源）：视频、文档、课件
- `ExamPaper`（试卷）：试题组成、分值配置、及格标准
- `ExamRecord`（考试记录）：考试时间、考试成绩、答题详情
- `LearningRecord`（学习记录）：学习进度、学习时长、完成情况

**领域服务**：
- `OnlineLearningService`：在线学习、进度跟踪
- `ExamService`：在线考试、自动阅卷
- `CertificateService`：证书生成、证书查询


#### 5.4.3 索引设计原则

- 主键索引：所有表必须有主键
- 唯一索引：业务编号字段（如设备编号、任务编号）
- 普通索引：高频查询字段、外键字段、状态字段
- 联合索引：多字段组合查询场景
- 避免过多索引：单表索引不超过5个
