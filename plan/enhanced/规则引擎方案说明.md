# 燃气监管平台规则引擎方案说明

> 更新日期：2026-01-30
> 版本：v1.0

---

## 一、方案背景

在设计燃气安全监管平台的技术架构时，最初计划引入 **Drools 8.x** 作为规则引擎来处理报警规则、风险评估规则和燃沼辨识规则。

经过对 ruoyi-vue-pro 框架的深入调研，发现 **IoT 模块已经内置了一套成熟的自研规则引擎**，完全可以满足燃气监管平台的需求。

---

## 二、技术调研结果

### 2.1 ruoyi-vue-pro IoT 模块规则引擎

**位置**：`yudao-module-iot/yudao-module-iot-biz/src/main/java/cn/iocoder/yudao/module/iot/service/rule/`

**核心组件**：

| 组件 | 说明 |
|------|------|
| IotSceneRuleMatcherManager | 规则匹配器管理器，统一管理所有匹配器 |
| IotSceneRuleTriggerMatcher | 触发器匹配器（主条件） |
| IotSceneRuleConditionMatcher | 条件匹配器（子条件） |
| IotDataRuleService | 数据流转规则服务 |
| IotSceneRuleService | 场景规则服务 |

**技术实现**：
- ✅ 基于策略模式 + 责任链模式
- ✅ 轻量级，无需引入 Drools 等重量级框架
- ✅ 支持优先级排序
- ✅ 支持动态加载匹配器
- ✅ 内置缓存机制（使用 Spring Cache）

**规则类型**：
- 场景规则（Scene Rule）：设备属性/事件/服务/状态触发器、定时触发器
- 数据流转规则（Data Rule）：HTTP/WebSocket/Kafka/RabbitMQ/Redis/TCP 数据转发

## 三、方案对比

### 方案一：引入 Drools（❌ 不推荐）

**优点**：
- ✅ 功能强大，支持复杂规则
- ✅ 社区成熟，文档丰富

**缺点**：
- ❌ 增加依赖复杂度（需要引入多个 Drools 相关依赖）
- ❌ 学习成本高（需要学习 DRL 语法）
- ❌ 与框架风格不一致（ruoyi-vue-pro 倾向于轻量级）
- ❌ 对于当前需求过于重量级
- ❌ 增加维护成本

### 方案二：复用 IoT 规则引擎架构（✅ 推荐）

**优点**：
- ✅ 复用成熟的架构设计
- ✅ 轻量级，无需引入 Drools
- ✅ 易于维护和扩展
- ✅ 与框架风格一致
- ✅ 开发效率高（参考 IoT 模块实现）
- ✅ 性能优秀，支持高并发

**缺点**：
- ⚠️ 需要针对燃气业务定制匹配器（但工作量可控）

---

## 四、最终方案

### 4.1 方案选择

**采用方案二：复用 IoT 规则引擎架构**

### 4.2 实现策略

#### 4.2.1 架构设计

```
燃气规则引擎架构
├── GasRuleMatcherManager（规则匹配器管理器）
│   ├── 触发器匹配器
│   │   ├── GasConcentrationTriggerMatcher（浓度触发器）
│   │   ├── GasVibrationTriggerMatcher（振动触发器）
│   │   ├── GasPressureTriggerMatcher（压力触发器）
│   │   └── GasThresholdExceedTriggerMatcher（阈值超限触发器）
│   └── 条件匹配器
│       ├── GasThresholdConditionMatcher（阈值条件）
│       ├── GasTrendConditionMatcher（趋势条件）
│       ├── GasDurationConditionMatcher（持续时间条件）
│       └── GasLocationConditionMatcher（位置条件）
└── 规则执行器
    ├── AlarmRuleExecutor（报警规则执行器）
    ├── RiskRuleExecutor（风险评估规则执行器）
    └── MethaneRuleExecutor（燃沼辨识规则执行器）
```

#### 4.2.2 模块结构

```
yudao-module-gas-rule/
├── yudao-module-gas-rule-api/
│   ├── enums/
│   │   ├── GasRuleTriggerTypeEnum.java
│   │   ├── GasRuleConditionTypeEnum.java
│   │   └── GasRuleActionTypeEnum.java
│   └── dto/
│       ├── GasRuleDTO.java
│       └── GasRuleResultDTO.java
└── yudao-module-gas-rule-biz/
    ├── matcher/
    │   ├── GasRuleMatcherManager.java
    │   ├── trigger/（触发器匹配器）
    │   └── condition/（条件匹配器）
    ├── executor/（规则执行器）
    ├── service/（规则服务）
    └── dal/（数据访问层）
```

#### 4.2.3 规则配置示例

```json
{
  "ruleName": "可燃气体浓度报警规则",
  "trigger": {
    "type": "CONCENTRATION",

  },
  "conditions": [
    {
      "type": "DURATION",
      "operator": ">=",
      "value": 60,

  ],
  "actions": [
    {
      "type": "ALARM",

  ]
}
```

## 六、技术优势

### 6.1 与 Drools 对比

| 对比项 | Drools | 自研规则引擎 |
|--------|--------|-------------|
| 依赖复杂度 | 高（多个依赖包） | 低（无额外依赖） |
| 学习成本 | 高（DRL 语法） | 低（Java 代码） |
| 框架一致性 | 低 | 高 |
| 维护成本 | 高 | 低 |
| 性能 | 优秀 | 优秀 |
| 扩展性 | 强 | 强 |
| 适用场景 | 复杂规则 | 中等复杂度规则 |

### 6.2 核心优势

1. **轻量级**：无需引入重量级框架，减少依赖
2. **易维护**：基于 Java 代码，易于调试和维护
3. **高性能**：基于策略模式，性能优秀
4. **易扩展**：支持动态加载匹配器
5. **框架一致**：与 ruoyi-vue-pro 风格一致
